# Анализ фронтенд кодовой базы: Imagus Mass Downloader Mod (MV2)

## 📁 Структура проекта

```
c:\Users\sucot\ImagusMassDownload\
├───src/            # Основной исходный код расширения (логика, UI, ресурсы)
├───bin/            # Бинарные файлы, включая Closure Compiler для сборки
├───minified/       # Минимизированная версия файла правил sieve.jsn
├───unminified/     # Несжатая версия исходного кода для разработки
├───MDMassive/      # Похоже на отдельную, возможно, экспериментальную версию проекта
├───Backups/        # Резервные копии предыдущих версий
├───build.py        # Скрипт для сборки расширения
├───*.md            # Файлы документации и анализа
└───*.jsn           # Файлы конфигурации и данных (правила, локали)
```

**Принцип организации кода:** Проект использует **слоевую (layer-based)** архитектуру. В директории `src` код разделен по функциональному назначению: `js` для логики, `css` для стилей, `includes` для скриптов контента и отдельные HTML-файлы для разных частей расширения (popup, options, background).

## 🏗 Архитектура

*   **Компонентная архитектура:** Отсутствует. UI создается и управляется императивно.
*   **Управление состоянием:** Состояние разбросано по объекту `PVI` и DOM-атрибутам.
*   **API-слой:** Взаимодействие с фоновым скриптом происходит через `Port.send`.
*   **Паттерны:**
    *   **Событийная модель (event-driven):** Типичная для расширений Chrome.
    *   **Глобальный объект (`PVI`):** Инкапсулирует всю логику на стороне клиента.
    *   **Двухэтапная очередь:** Для управления массовой загрузкой.
    *   **Движок Sieve:** Для поиска и преобразования URL.

## 🎨 UI/UX и стилизация

*   **Стилизация:** Проект использует чистый CSS. Страница настроек имеет отдельный CSS-файл (`options.css`), в то время как страница прогресса загрузки использует встроенные стили. Стилизация функциональна и чиста, но не очень современна.
*   **UI:** Пользовательский интерфейс построен на стандартном HTML и разделен на разные страницы для разных функций (настройки, прогресс загрузки, всплывающее окно). Страница настроек представляет собой одностраничное приложение с маршрутизацией на основе хеша.

## ✅ Качество кода

*   **Линтеры:** Отсутствуют. Автоматическая проверка стиля кода не настроена.
*   **Тесты:** Отсутствуют. В проекте нет юнит-тестов, интеграционных или e2e тестов.
*   **Соглашения по коду:** Код написан на чистом JavaScript. Именование в целом последовательное, но формальный стайлгайд отсутствует. Код слабо-модульный, с большими файлами, содержащими много логики (например, `content.js`). Использование единого глобального объекта (`PVI`) является устаревшим паттерном.
*   **Документация:** Комментарии в коде есть, но они не исчерпывающие. Формальная документация, такая как JSDoc, отсутствует.

## 🔧 Ключевые компоненты

*   **`PVI` object in `content.js`:** Ядро логики на стороне клиента. Он обрабатывает все: от поиска изображений до отображения всплывающего окна и управления процессом массовой загрузки.
*   **`downloadAll` function in `content.js`:** Точка входа для функции массовой загрузки. Она запрашивает в DOM все потенциальные медиафайлы, фильтрует их, а затем отправляет в фоновый скрипт для загрузки.
*   **`background.js`:** Ядро фоновой логики расширения. Он обрабатывает очередь загрузки, фильтрацию и связь со скриптами контента и другими частями расширения.
*   **`sieve.jsn`:** Правила для поиска изображений в высоком разрешении. Это основа способности расширения находить изображения наилучшего качества.
*   **`options.html` and `options.js`:** Страница настроек. Она позволяет пользователю настраивать поведение расширения, включая правила `sieve`.
